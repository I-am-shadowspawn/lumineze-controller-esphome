# T03 — Ownership map and control contract

Design checkpoint written against the monolithic `packages/lumineze-controller.yaml` at source baseline `7cbc718`. T05 mechanically separated it as recorded in `docs/t05-extraction.md`; the common control contract below remains a T06 design, not current behaviour. The first implementation mechanism is **parameterised ESPHome scripts plus explicitly owned globals**. A generic C++ framework is unnecessary for two fixed lamp slots.

## Proposed evaluation and output contract

One orchestrator takes a snapshot once per 10-second evaluation. The snapshot contains `valid`, actual source/provider, local year, day-of-year, days-in-year (365/366), local minutes since midnight including seconds as a fraction, and whether the input is simulated. It is immutable for that evaluation. Invalid/non-finite values make the snapshot invalid; the engine does not read `controller_time` or test entities directly. The real provider uses the controller's configured timezone. Transaction, retry and grace timers continue to use monotonic `millis()`; a simulated day or clock correction cannot accelerate them.

Each engine produces `{valid, desired_fraction[2], reason}` for the same snapshot. Slot 0 is JungleDawn, slot 1 ProT5. Fractions are finite values in `[0, 1]`: 0 means off; 1 means 100% of that lamp's configured maximum. Seasonal scale and curve shape are engine-owned; the daily schedule will convert its configured percent to a fraction. The engine never sees BLE IDs, transaction state or lamp MACs. Invalid/non-finite engine output is rejected by control and follows the invalid-output policy assigned to T06; it is never cast into a BLE byte.

Common control converts an authorised fraction to lamp percent **once** using `std::lround(maximum_percent * fraction)` and clamps the result to `[0, 100]`. Manual input is an integer percent and passes through the same maximum cap. ProT5's calibrated maximum of zero produces zero. This preserves the current seasonal calculation's effective `lround(maximum * seasonal_scale * curve)` ordering; compare exact targets at baseline cases before replacing its existing calculation. The queue receives only a final integer percent and does no engine-specific arithmetic. During T05, the existing queue's cap remains in place until the shared conversion is actually moved; never apply the cap twice.

Priority per lamp is: (1) disabled/uncommissioned lamp: no operational queueing; (2) explicit safety decision such as invalid-clock safe-off after its grace period; (3) explicit safe-off; (4) active manual override/latest manual request; (5) automatic request if enabled and snapshot/engine valid; (6) hold current request. The baseline's invalid-clock path requests zero even with manual override, but whether this should remain the final policy is assigned to T06. Switching automatic off currently holds state rather than sending zero. The dispatcher keeps the latest pending target; a new target during an in-flight write does not rewrite that wire transaction and is sent afterward if still authorised. T06 must verify cancellation and stale request handling on a bench.

The shared state names mean different things: **requested** is the latest authorised final target; **pending** means it awaits dispatch/retry; **in-flight** is the target copied when a transaction starts; **completed** means the transaction write path finished; **reported** is the last valid lamp notification, with freshness tied to the last command. A missing/stale report is unknown physical output, even after a successful write or safe-off request. Diagnostics expose these separately.

## Verification and open policy decisions

- T05 extraction must preserve a resolved-config inventory: one owner for each ID, two BLE clients, one 10-second evaluation and one 1-second dispatch interval, no duplicate callbacks, unchanged entity names and restore settings.
- T06 settles invalid engine output, manual override during invalid time, commissioning and safe-off precedence, latest-target handling after reconnect, and whether restoring automatic settings can command a lamp before time is valid.
- T07 settles whether simulation may drive physical lamps and removes development IDs from production builds. T08 chooses the production diagnostic subset. T10 specifies schedule time/DST semantics.
- T01's field observations remain open. Neither this design nor a firmware compile proves the hardware behaves as intended.
